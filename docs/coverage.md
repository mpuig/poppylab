# Poppy 1.0 coverage matrix: Iris, Juniper, Lantern, Harborline, Northwind and Fernwick

This describes the current implementation against **Personal Agent Protocol 1.0** and the **Operations extension, version 3**. **It does not certify conformance**: it is a map of capabilities, limits and evidence, not an inventory of every MUST and SHOULD. The text is pinned in `spec/1.0/` (published 14 November 2026, retrieved 25 November); `pnpm spec:drift` reports later changes. Details in [Poppy 1.0](poppy-1.0.md).

**Iris** is the Personal Agent in the playground. **Juniper Market**, **Lantern Noodle Bar**, **Harborline Bank**, **Northwind Air** and **Fernwick Power & Light** are fictional Companies that share one gateway (`packages/pap-company`) with their own scopes, contracts, Company Agents and business. They run locally at ports 4100, 4200, 4300, 4400 and 4500; Wrangler configurations target `grocery-demo.poppylab.dev`, `food-demo.poppylab.dev`, `bank-demo.poppylab.dev`, `airline-demo.poppylab.dev` and `energy-demo.poppylab.dev` (the validator results below are for the first four; Fernwick was added after that run). Earlier versions (0.1–0.4) are not accepted.

**Validators.** The official validator from the [Company kit](https://personalagentprotocol.org/kit/company) passes 107 checks, fails none and warns on none at each of the five live Companies (26 November 2026); 26 are skipped because they test features the Companies don't offer. The community Poppy Demo Agent validator reports Juniper, Lantern and Iris's client metadata valid with 0 errors, 0 warnings and 0 info (25 November 2026). Details in [validator results](learn/validator.md).

Legend: **I** implemented (within the stated limits) · **P** partial · **N** not implemented · **—** not applicable. Evidence: **A** automated tests · **V** documented live check · **C** code inspection only.

`pnpm scenarios` groups tests by topic (`pap-1.0`, `conversations`, `noodles`, `banking`, `airline`, `permissions`, `revisions`, `operations`, `recovery`, `mcp`, `nonce`, `authority`).

## 6. Security and project limits

- Secrets (refresh and access tokens, Session JWTs, keys, codes and PKCE verifiers) stay out of the model context and the traces. Browser API keys live only for the request.
- **Public deployment:** each visitor has their own agent state in a Durable Object, sealed at rest with `POPPY_STATE_KEY`, and their own copy of each Company's fictional customers. Budgets per visitor, IP and globally; no client may hold more than a fifth of a Company's shared caps.
- Storage is single-writer (encrypted vaults on Node, one Durable Object per Company on Workers); there is no distributed coordination.
- **External demos:** see [community demos](community-demos.md).
- There has been no independent security review and no official conformance check.
